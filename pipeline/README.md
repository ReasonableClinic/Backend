# pipeline (오케스트레이터)

LLM이 순서를 정하지 않는, 코드로 된 실행기입니다. 흐름이 고정돼 있어서(1·2 → 3 → 4 → 5 반복 → 6) 규칙으로 충분하고, 그래야 dev/test 재현과 비교가 됩니다.

| 파일 | 내용 | 상태 |
| --- | --- | --- |
| `run_pipeline.py` | 에이전트 `run()`을 순서대로 부름, 모든 에이전트에 같은 `RUN_ID` 전달(추적 세션 연결), 연결 안 된 에이전트는 건너뜀 | 뼈대 (에이전트 연결되는 대로 동작) |
| `manifest.py` | 실행 기록: 입력·출력 파일 해시, 에이전트 버전, 소요 시간. `check_ids`: 판정이 가리키는 근거 ID가 근거 파일에 모두 있는지 확인하고, 없으면 멈춤 | 사용 가능 |

할 일 (정리 담당):
1. 에이전트 2·3 `run()` 연결 → `--only agent3`로 dev 한 번, 원본 실행과 결과 비교
2. 부분 재실행: 바뀐 환자·문서만 (에이전트 2 `update.py`, 에이전트 3 `--changes`)
3. 5번 고리: 답 → 2 갱신 → 3 부분 재판정 → 4 검증, `--loop N` 상한, 판정 변화 없으면 종료. LangGraph를 쓴다면 이 부분
