# Agent 2: evidence extraction (rules + Haiku 4.5, ①-b concepts)

```
python3 agent2/extract.py --patients data/dev/input/patients.jsonl --trials data/dev/reference/trials.jsonl --criteria-ref data/dev/reference/criteria.jsonl --out runs/dev_v2
python3 code/eval_evidence.py --gold data/dev/gold/gold.jsonl --pred runs/dev_v2/evidence.jsonl --patients data/dev/input/patients.jsonl --by doc_type
```

| file | role |
| --- | --- |
| `concepts.json` | team ①-b concept dictionary (138 keys, units, alt_units); `concepts_agent2.json` holds Agent 2's overlay (aliases, alt units, `tumor_marker` -> `biomarker`, skips). `concepts_provisional.json` is the pre-①-b list, kept for old runs only |
| `plan.py` | plan: top-k candidate trials by TF-IDF (title/conditions/MeSH vs record), vocabulary of their criteria; generic facts are kept only if they share a content word |
| `segment.py` | document -> fact units (line / sentence / measurement-list item) with exact spans |
| `rules.py` | sections, numeric labs/vitals + unit conversion, serology, lexicons, negation / family / suspected / reported / plan cues, dates |
| `extract.py` | pipeline + self-check (span equality, value range flag, date <= as_of, duplicates) + log.jsonl |
| `llm_layer.py` | LLM layer: every unit + rule hint -> facts (concept, value, certainty, subject, status, date, quote); validation, up to 3 rounds, rule fallback. `--relevance all|criteria` |
| `prompts.py` | prompt split into cacheable parts: static (instructions + concept list + 4 worked examples, ~5k tokens) / per patient (candidate-trial criteria) / units |
| `backends.py` | `openrouter` (dev, gpt-oss-120b), `anthropic`, `anthropic-batch` (final, Haiku 4.5, Batches API + prompt caching), `mock`; response cache on disk, usage and cost estimate |
| `RUN_LOCAL.md` | commands to run the LLM layer on a team PC (keys stay local) |
| `RUN_TEST.md` | the one procedure for the test run and its dev rehearsal: `preflight_inputs.py` -> Haiku batch -> `release.py` |
| `evidence_index.py` | Agent 3 lookup: `for_criterion` (①-b concept + related keys + baskets, time-window marks), `render` |
| `update.py`, `carry_ids.py` | update path (only new/changed documents re-extracted, `changes.jsonl`) and id carry-over between versions |
| `postfix.py` | apply `extract.lab_values` / `extract.post_fix` to a finished evidence file, ids kept |
| `preflight_inputs.py`, `release.py` | input check before a paid run; format checks, id carry, dev-only scoring and kit file after a run |
| `ablate.py`, `iou_misses.py` | analysis helpers |

Extra ③ fields: `term` (the matched word for generic concepts), `detail` (comparator, systolic/diastolic, unit_written, start date, plan_terms, status planned/declined, derived_from).
Dates: explicit > range end > YYYY-MM / MM/YYYY (first day) > MM-DD (doc year) > month name > "N days ago" / "last night" > year; "since X" on an ongoing fact = document date; masked/future -> null.

## Changes
- 2026-10-06 v2: numeric hints no longer read analytes inside ratios ("Urine protein/creatinine ratio 0.4" gave `creatinine=0.4`; 13 such hints on dev, reported by the team). Longest aliases match first, `X/Y` and "... ratio N" are skipped. Percentages are not taken as counts ("Neutrophils 62 %" gave `anc=62`, 12 on dev); the absolute count written next to it is used instead ("abs 6.0 x10^9/L"). Segmenter keeps "; abs ..." with its analyte and does not split at "...". Unit trailing dots stripped; `bpm`, `mL/min/1.73` added as alt units. Check: `python3 agent2/ratio_check.py`. Dev recall unchanged (0.970).
- 2026-10-06 v3 (speed/quality balance): units the rules read reliably (labs/vitals next to a known alias, demographics, serology, no negation/family/plan cue) are not sent to the model (about 21% of units). The model answers `{"u": N, "ok": true}` when the hint is right and omits default fields (shorter output = faster). 30 units per request, 8 in parallel, retries in smaller requests, gpt-oss reasoning `low`, 120 s deadline. `--online` processes one patient at a time and records seconds per patient; `usage.json` has request and patient latency percentiles.
- 2026-10-06 v4: a truncated answer (output limit hit mid-JSON, seen as `bad_json` with gpt-oss) keeps every complete unit; units the answer never reached are re-asked instead of dropped (`truncated_answer_salvaged` in checks). `max_tokens` = 4000 + 150 per unit, because gpt-oss counts hidden reasoning in it. Mock with `MOCK_TRUNCATE=0.6`: fallback to rules falls from a whole request to about 15 units per patient.
- 2026-10-06 v5 (from the first real gpt-oss answers, replayed with `--provider replay` and `AGENT2_REPLAY=<answers.jsonl>`): 1 of 14 answers broke down mid-generation (runs of non-breaking spaces) and silently dropped the rest of its units, which cost 10 of 12 missed gold evidence. Now every unit must appear in "units" or in a "drop" list; units not covered are re-asked, and still uncovered after round 3 fall back to rule facts. Broken answers (non-breaking space or whitespace runs) are rejected and re-asked in smaller requests. Enum values are trimmed. 110 of 251 answered units only restated a correct hint (45% of output characters): the prompt now makes `ok` the preferred answer for a correct hint. Replay of the old answers with these checks: recall on the 2 patients 0.878 -> 0.990.
- 2026-10-06 v6 (from the v5 gpt-oss answers): the model's "drop" lists were sloppy (ids of units it had answered, ids outside the request, and some real facts: 6 of 67 dropped units were gold evidence). Safety net: a dropped unit keeps the rule facts that are explicit denials, specific concepts, or lexicon drugs/procedures. Segmenter: a colon splits only after a section heading, so "Relapses: 0.", "Dynamic CT: 3 lesions", "Stage: ..." stay one unit (rule recall 0.970 -> 0.972). Latency: patient time was round 1 plus a whole round 2 for as few as 3 leftover units; now fewer than `--min-retry` (5) leftover units go to rule facts at once. Defaults `--chunk 15 --workers 16` (all requests of a patient in parallel, shorter answers).
- 2026-10-06 v7 (full dev, gpt-oss, replayed): spans are whole units again (`AGENT2_SPAN=unit`, quote kept in `detail.quote`): the model often quotes only part of a unit, and unit spans scored higher on both recall and IoU. Specific rule facts the model's answer left out are added (`rule_facts_added_to_llm`, e.g. TSH/T3 next to a TRAb-only answer); the drop safety net also keeps medications from the meds section, medication records or with a dose.
