# 2층 전문가 평가 진행안 (a6-0.4.5, dev만)

자동 검사(1층)는 문장이 근거와 **어긋나지 않는지**만 봅니다. 2층은 사람이 **읽기 쉬운지, 오해가 없는지, 의료진에게 쓸모 있는지**를 봅니다. 틀 문장과 LLM 브리핑을 가리고 같은 기준으로 매깁니다. **test 환자는 쓰지 않습니다.**

## 1. 표본 (정함, `scripts/eval2_kit.py`)

- **dev 기본 환자 19명 중 12명.** 변형 환자는 기본 환자와 문서 하나만 달라 문장이 거의 같아서 넣지 않습니다.
- 성질이 하나씩은 들어가게 먼저 고르고(시드 2026, 다시 돌려도 같은 표본), 나머지는 내용이 많은 브리핑 순으로 채웁니다.

| 들어가야 할 성질 | 표본에서 |
| --- | --- |
| 미성년(보호자 안내) | SYN-0001 |
| 기록 진단이 대상 조건과 맞는 문장 | SYN-0001·0002·0006·0010·0013·0018·0019 |
| 재확인 표시(review_flags) | SYN-0002·0006 |
| near-miss(FAIL 하나로 제외) | SYN-0002·0003·0006·0007·0012·0015 |
| 순위 시험 0 / 1 / 2 / 3개 | SYN-0015 / 0001·0003·0006·0007·0012 / 0002·0010·0017·0019 / 0013·0018 |
| LLM 틀 문장 대체가 있는 환자 | LLM 폴더(`--llm`)를 주면 `llm_log.jsonl`로 반영(이 성질 때문에 표본이 1명 바뀔 수 있음. 위 표는 틀 문장만으로 고른 표본) |

- **표본에 없는 것:** "암 진단 없는 환자에게 질환명을 숨긴" 경우가 dev에 없습니다. 이 항목은 외부 회귀(TREC·SIGIR, 0/203)가 계속 맡습니다.
- 12명이 모두 환자용 점검표를 받고, 그중 **6명**(SYN-0001·0002·0006·0013·0015·0018)은 의료진용을 문장 단위로 매깁니다. 의료진용 문장이 브리핑마다 70개 안팎이라 전부 하면 평가자 부담이 너무 커서입니다.

## 2. 무엇을 매기나

**환자용 (환자 1명 × 버전마다 13문항, 1=그렇다 / 0=그렇지 않다 / NA)**
- 이해(U1~U5), 행동(A1~A2), 치료적 오해(M1~M3), 고지(K1~K2), 안전(S1: 확정되지 않은 진단을 단정하지 않음)
- 문항은 PEMAT·CDC CCI·KGCP의 **영역을 따라 우리가 쓴 문장**입니다. 원 도구의 문항을 그대로 옮긴 것이 아니므로, 보고서에는 "영역 기반 자체 점검표"로 적습니다. PEMAT 원문 대조는 아직입니다(EVAL_PLAN 인용 상태).

**의료진용 (문장마다)**
- 그 문장이 인용한 근거(묶음 파일에 문장 바로 밑에 펼쳐 둠)와 비교해 3=지지됨 / 2=일부 / 1=근거 없음 / 0=모순
- 1·0이면 심각도: 치명(환자 안전이나 참여 판단을 바꿈) / 중대(의료진이 잘못 확인할 수 있음) / 경미(표현 문제)

## 3. 진행

1. **조정자**(평가자가 아닌 사람 1명)가 묶음을 만듭니다.
   ```bash
   python3 scripts/eval2_kit.py --template dev_out/briefing --llm runs/brief_llm_dev \
       --ranking dev_out/ranking.jsonl --graphs <dev graph 폴더들> --out runs/eval2
   ```
   `runs/brief_llm_dev`는 팀 키로 돌린 LLM dev 출력입니다(`run_llm.sh`). 없으면 틀 문장만 나옵니다.
2. 평가자에게는 `packets/`와 `forms/`만 줍니다. 버전은 A·B로만 보이고 환자마다 순서가 섞여 있습니다. **`key.json`과 `sample.csv`는 조정자만 갖습니다.**
3. 평가자는 서로 상의하지 않고 각자 `forms/*.csv`를 채웁니다. 먼저 환자 1명으로 연습하고 기준을 맞춘 뒤, 연습분은 결과에서 뺍니다.
4. 조정자가 일치도와 결과를 냅니다.
   ```bash
   python3 scripts/eval2_agree.py --key runs/eval2/key.json \
       --clinician 평가자1/clinician_form.csv 평가자2/clinician_form.csv \
       --patient 평가자1/patient_form.csv 평가자2/patient_form.csv
   ```
   - 일치도: 의료진용 4단계는 선형 가중 κ(평가자 2명) + Krippendorff α(순서형), 환자용 1/0은 κ + α(명목형). 계산은 Krippendorff(2011) 예제 값(명목 0.743, 순서 0.815)과 sklearn 가중 κ로 확인했습니다(단위 테스트).
   - 결과: 버전별(틀 문장 / LLM) 지지됨 비율, 근거 없음·모순 비율과 심각도, 환자용 "그렇다" 비율.
   - 보고 기준: 일치도가 낮으면(α < 0.67) 결과를 확정하지 않고 기준을 다시 맞춘 뒤 다시 매깁니다.

## 4. 평가자 (팀이 정할 것)

| 대상 | 제안 | 정할 것 |
| --- | --- | --- |
| 의료진용 문장 | 의학 지식이 있는 평가자 **2명** (임상시험 기준을 읽을 수 있는 사람) | 누가 할지 |
| 환자용 점검표 | **2명 이상**. 1명은 의료진용 평가자, 1명은 비전공자면 이해도 쪽이 더 잘 보입니다 | 누가 할지, 비전공자를 넣을지 |
| 조정자 | 평가자가 아닌 1명 (묶음 만들기, key 보관, 계산) | 누가 할지 |

- **부담 (dev 틀 문장 기준):** 환자용 12명 × 13문항 × 2버전 = 312칸, 의료진용 6명 × 약 76문장 × 2버전 ≈ 900문장. 의료진용이 크면 `--clinician-n 3`으로 줄일 수 있습니다(그만큼 성질 범위가 좁아짐).
- **IRB:** 팀원이 문서를 매기는 것은 텍스트 평가입니다. 팀 밖 사람(특히 의대·간호대 등 학생)을 평가자로 모집하면 3층과 같은 IRB 검토 대상인지 학교 IRB에 먼저 확인합니다(EVAL_PLAN 3층).
- 시험 실행: 시뮬레이션 평가자 2명으로 묶음 → 채점 → 일치도 계산까지 돌려 형식을 확인했습니다(실제 평가 결과 아님).
