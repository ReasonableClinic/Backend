- 남은 숫자 누락(15%)은 대부분 두 가지입니다. 하나는 "1가지 → 2"처럼 작은 개수가 다른 개수와 우연히 같은 경우, 다른 하나는 영어 원문 안의 숫자(약 코드 "R3R01" 등)입니다.
- 남은 영어(20.4%)는 질환명(연구 대상 문장)과 진단명입니다. 다음 단계는 검토된 질환 용어 사전입니다. dev 환자용에 나오는 질환은 28개, 시험 197개 전체로도 225개입니다.

### LLM 브리핑 설계 (`brief_llm.py`)

1. 코드가 그래프로 시험별 사실 묶음을 만듭니다. 환자용 사실은 틀 문장과 같은 `keyinfo.patient_facts`에서 나옵니다(`T1.label`, `T1.studies`, `T1.confirmed`, `T1.route_tests`, `T1.excl` …).
2. LLM은 사실 id만 인용합니다. 노드 ID는 코드가 붙입니다.
3. 고정 문구는 코드가 넣습니다. 첫머리에는 연구라는 사실과 보호자 안내, 각 시험 뒤에는 설계 문구, 끝에는 효과 미확인·질문 안내·의료진 확인·자발성·철회가 들어갑니다.
4. 검사에 실패하면 1번 다시 요청하고, 그래도 실패하면 그 시험만 틀 문장으로 바꿉니다(`llm_log.jsonl`).
5. 의료진용은 LLM 요약 + 세부 판정 + near-miss 목록입니다.

- 모델: 기본 `claude-sonnet-5-5`. temperature는 보내지 않습니다(받는 모델이면 `AGENT6_TEMPERATURE=0`).
- 프롬프트: 환자용 `pb07`, 의료진용 `cb02`(이력: pb03 공식 제목 제거, pb04 용어 사전, pb05 암 문구, pb06 사전 밖 용어 번역 금지, pb07 사전 밖 용어는 번역하되 원어를 남김). 환자용 첫 줄은 "N번 시험 — 판정"(공식 제목 없음). 순서는 판정 → 연구 대상 → 기록에서 맞는 조건 → 누가 답할지별 남은 확인 → 제외 개수 → 모집입니다.
- 캐시: `runs/.llm_cache/` (돌려줄 때 넣지 않음).
