## 3. 시도했으나 미채택: p08 → p10

v2 보고 "다음 할 일 2": 인용하고도 UNSUPPORTED 34건(정답 v7 기준 35건) 분류 → 프롬프트 p08 → dev 1회.

**분류** (`runs/analysis_unsupported_cited_v2.csv`): (a) 19건 — 기록에 값·등급·날짜가 있고 선정 기준 문턱에 못 미침, 또는 제외 범주의 명백한 구성원인데 "정도 미기록"으로 UNKNOWN(정답 FAIL). (b) 16건 — "investigator confirmation", "central read", "clinically significant"를 글자 그대로 막는 조건으로 읽음(정답 PASS).

| 판 | 내용 | 기준 일치 | 반대 방향 | 확정 정답 UNKNOWN | 정답 UNKNOWN 확정 | 시험 판정 |
| --- | --- | --- | --- | --- | --- | --- |
| p08 | 노션 범위(용어 해석) + **담당자 확장**(값이 요건 미달이면 FAIL, MISSING 전 회상 점검) | 81.5% | 4 | 45 | 77 | 94.4% |

- 반대 방향 오류 10건(p08·p09)은 모두 **선정 기준을 FAIL로 밀어낸 것** — 담당자가 노션 진단("용어를 지나치게 엄격하게 읽음")을 넘어 결정 문턱을 낮춘 규칙이 원인. 날짜 계산 오류, 모델 외부 지식, 노트-상태 자기모순이 FAIL로 확정됨.
- p10은 노션 범위 안이고 합격선(≤1%)도 통과하지만, UNKNOWN은 Agent 4·5가 질문으로 채우는 **정당한 출력**이고 잘못된 FAIL은 Agent 4·5를 그대로 통과해 환자에게 "부적합"으로 보이므로, 팀 철학(근거 뒷받침)에 따라 **보수안 p07로 고정**. p10의 개선(UNKNOWN 125→72, 질문 카드 감소)은 Agent 4 노트-상태 검사가 자리 잡은 뒤 재검토할 후보로 남김.
- MISSING 33건(정답 v7 기준 38건, 정책 격하 제외) — v2 보고 "다음 할 일 3": `missing_check.py`로 확인한 결과 **Agent 2 누락 0건**(모두 정답 위치에 근거 있음). `for_criterion` 선별은 38건 중 7건을 가려 채택 보류. 원인은 LLM 회상(NKDA 5, 클래스 부정문 8, 완결 열거 3, 배타 범주 2, A3 쟁점 ~6 등) — 프롬프트 변경은 미채택(p08 24번 규칙이 과확정 29→77의 주원인).

## 4. Agent 4 인계 (`handoff_agent4/`)

- `dev_agent3_out_v3_p07/`: v3 dev 출력(1회차) + Evidence Graph — Agent 4 첫 입력. 변형 세트 페이지의 `agent3_out_v2_p06` 자리에 교체 요청.
- Agent 3이 더 이상 하지 않는 검사 목록과 v2 작동 횟수 → `handoff_agent4/README.md`.
- **추가 요청**: 검사 1~4 외에 **노트-상태 일치 검사**(노트가 "arguable/borderline/not met"인데 확정 → UNKNOWN/UNSUPPORTED + clinician_confirmation). 오늘 반대 방향 오류의 절반이 이 유형이고, 근거 인용은 맞아서 grounding·개념·만료 검사로는 안 잡힘. v2 `HEDGE_RX`를 그대로 옮기면 됨.
- 모델 지식 오류(KRAS G12V 유형)는 Agent 4가 코드로 잡기 어려움 → `clinician_confirmation` 경로로 보내는 규칙(바이오마커·약물 승인 여부 관련 FAIL은 의료진 확인) 검토 요청.
